# WEEK 9 — Planning, reasoning, reflection, memory
**Oct 26–30** · Designated tool: Cowork

Week 7 gave you an agent that reacts. This week gives it the ability to plan ahead, notice it was wrong, and remember across sessions. Memory in particular is where most production agent projects quietly fail — teams bolt on a vector store, call it memory, and discover that retrieval-based recall is not the same thing as knowing what happened.

| Block | Work |
|---|---|
| **Mon AM** | Planning approaches: ReAct's implicit planning vs plan-and-execute, decomposition, and Tree of Thoughts (Yao et al.). When does explicit upfront planning beat step-by-step reaction? |
| **Mon PM** | Add a plan-and-execute mode to your agent. Make the plan inspectable and revisable — a plan you can't see is a plan you can't debug. |
| **Tue AM** | Reflection and self-correction. Read Reflexion (Shinn et al.) and Self-Refine. This is JHU's "verbal RL" — learning from feedback in language rather than weights. Understand honestly where reflection helps and where it just burns tokens agreeing with itself. |
| **Tue PM** | Implement a reflection loop with a hard iteration cap. Measure whether it actually improves task success on your eval suite, or only appears to. |
| **Wed AM** | Memory architectures. Working vs episodic vs semantic vs procedural memory. Read MemGPT and Generative Agents (Park et al.) for the reflection-and-retrieval design. Then study AgentCore Memory's model — short-term vs long-term, and strategy-based extraction. |
| **Wed PM** | Wire AgentCore Memory in. Prove cross-session continuity with a real multi-session task. |
| **Thu AM** | Skills, procedural memory, and progressive disclosure — how agents accumulate reusable capability instead of relearning each time. Tie this back to Week 3's context budgeting: skills are a context-efficiency strategy. |
| **Thu PM** | Harden: memory poisoning risk, stale-memory failures, contradiction handling, and a memory eviction policy. |
| **Fri AM** | Frontier watch. |
| **Fri PM** | **GATE 9.** |

**Deliverable:** `week09/` — agent with inspectable planning, a reflection loop with measured effect on eval scores, AgentCore Memory integration with demonstrated cross-session continuity, and a written memory-risk analysis.

**Oral exam:**
1. When does explicit planning beat ReAct-style reaction, and when is it wasted overhead?
2. Your reflection loop improved eval scores 3%. Worth tripling token cost? What else do you need to know?
3. Distinguish episodic, semantic, and procedural memory in an agent. Give a use case for each.
4. What is memory poisoning and how do you defend against it?
5. Two memories contradict each other. What's your resolution strategy?

# WEEK 12 — Security & safety for agentic systems
**Nov 16–20** · Designated tool: Kiro

Agentic security is genuinely unsolved, and being able to speak precisely about *why* is a strong senior signal. The core problem is structural: an LLM cannot reliably distinguish instructions from data, so any agent that reads untrusted content and holds privileges is exposed. That's not a bug to patch, it's a property to architect around — and architecting around unfixable properties is what you already do for a living.

| Block | Work |
|---|---|
| **Mon AM** | Prompt injection: direct and indirect. Read Simon Willison's writing on the "lethal trifecta" — private data, untrusted content, and external communication. Understand why this is architectural, not a filtering problem. |
| **Mon PM** | Red-team your own Project 2. Attempt indirect injection through documents it ingests. Document what worked. |
| **Tue AM** | Tool poisoning and the MCP supply chain: malicious server descriptions, rug-pull updates, confused-deputy problems, and over-broad OAuth scopes. |
| **Tue PM** | Build a sandboxed tool execution path. Use AgentCore Code Interpreter and reason about its isolation model versus running code in your own process. |
| **Wed AM** | Least privilege for agents: IAM design for non-deterministic callers, scoped credentials, human-in-the-loop approval gates for irreversible actions, and audit trails. |
| **Wed PM** | Implement Bedrock Guardrails plus your own input/output filtering. Then try to bypass your own controls. |
| **Thu AM** | Safety and alignment concepts you'll be asked about: Constitutional AI, RLHF's role in refusal behavior, jailbreak taxonomy, PII handling, and where guardrails genuinely help versus create false confidence. |
| **Thu PM** | Write the threat model: STRIDE-style, adapted for agentic systems. Trust boundaries, assets, attack paths, mitigations, accepted risks. |
| **Fri AM** | Frontier watch. |
| **Fri PM** | **GATE 12.** |

**Deliverable:** `week12/` — red-team report with successful and failed attacks documented, sandboxed execution path, Guardrails implementation plus bypass attempts, and a complete written threat model with explicitly accepted risks.

**Oral exam:**
1. Explain the lethal trifecta. Why can't you filter your way out of it?
2. A customer wants an agent that reads customer emails and can issue refunds. Design the controls.
3. What's tool poisoning in MCP, and how do you defend a fleet of MCP servers?
4. Design an IAM strategy for an agent whose actions you can't fully predict.
5. Your guardrails block 99% of attacks. Why might that be worse than blocking 60%?
